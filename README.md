# NiftyGEX: Long Attention, Short Gamma

CS 7150 Deep Learning term project by Bhalchandra Shinde and Asad Mulani.

Traders compress the NIFTY option chain into one number, gamma exposure (GEX). We ask whether a model that reads every contract (self-attention over about 70 option contracts per snapshot, plus a GRU over the last hour of snapshots) forecasts next-day volatility better than GEX-based, classical and tree-based models.

## Research questions

| | Question | Test (pre-registered in `configs/eval.yaml`) |
|---|---|---|
| RQ1 | Does reading every contract predict better? | Attention + GRU against every classical model, on the same 26 walk-forward test periods |
| RQ2 | Which part matters? | Switch off cross-contract attention (DeepSets) and history (single snapshot); Holm correction |
| RQ3 | Does it survive rule changes? | Gain before vs after the November 2024 weekly-expiry rationalisation (Welch t) |

Follow-up experiments E1–E3 and checks A1–A4 are exploratory, registered separately in `configs/eval_exploratory_v2.yaml` and `configs/eval_exploratory_v3.yaml` before their runs.

## Results

All results are generated by scripts from the results store:

- **RQ1–RQ3:** [`docs/findings_models.md`](docs/findings_models.md). Attention + GRU has the lowest forecast error (RMSE and QLIKE) of the eight models and ranks next-day volatility on par with the best classical models; the pre-registered rule (a significant ranking gain over every classical model) is not met.
- **Attention maps:** [`docs/findings_attention.md`](docs/findings_attention.md).
- **Exploratory:** [`docs/findings_exploratory_summary.md`](docs/findings_exploratory_summary.md) (E1–E3) and [`docs/findings_exploratory_v3.md`](docs/findings_exploratory_v3.md) (A1–A4): the option chain adds information as a correction to a simple volatility model, including one that uses implied volatility.
- **Data and baselines:** [`docs/findings_data.md`](docs/findings_data.md), [`docs/findings_forecast.md`](docs/findings_forecast.md), [`docs/validation_report.md`](docs/validation_report.md).
- **Reproducibility:** [`docs/findings_reproducibility.md`](docs/findings_reproducibility.md): a rerun from a clean commit reproduces every data file and prediction.
- **Terms:** [`docs/glossary.md`](docs/glossary.md).

## Repository layout

```text
src/niftygex/        data layer: cleaning, pricing, GEX, features, tokens, targets (no modelling)
src/niftygex_eval/   evaluation layer: walk-forward harness, classical and neural models, statistics, results store
scripts/             one entry point per stage, model run or report
configs/             data, regimes, evaluation and exploratory configs; path profiles
hpc/                 job scripts for the exploratory GPU runs (Northeastern Explorer; see docs/hpc.md)
tests/               unit, leakage and stage-contract tests
docs/                schema, pricing, evaluation design, findings, glossary, project status
notebooks/           walk-through notebooks (read only)
```

The evaluation layer reads only the data layer's Parquet outputs and manifests. Every stage manifest and model run records its config hash, git commit and whether the working tree was clean.

## Setup

```bash
conda env create -f env/environment.yml
conda activate niftygex
```

The market data are private and not included. Paths come from `configs/paths.local.yaml` (override with `NIFTYGEX_PROFILE` or `NIFTYGEX_DATA_ROOT`).

## Running

From the repository root, with `PYTHONPATH=src`:

```bash
# 1. Import the raw archive once (copy-only; data/raw/ is never modified afterwards)
python scripts/import_raw.py --source-root /path/to/archive --copy

# 2. Data pipeline (about 3 minutes)
python scripts/clean_chain.py
python scripts/compute_basis.py
python scripts/compute_forward.py
python scripts/compute_greeks.py
python scripts/compute_gex.py
python scripts/compute_features.py
python scripts/compute_tokens.py
python scripts/compute_targets.py
python scripts/validate_data.py          # fails on any timestamp or leakage violation

# 3. Models and pre-registered tests
python scripts/run_forecast.py           # classical models
python scripts/run_neural.py --save-attention   # DeepSets, self-attention, attention + GRU
python scripts/run_rq_tests.py
python scripts/report_results.py         # docs/findings_models.md
python scripts/report_attention.py       # docs/findings_attention.md

# 4. Exploratory tests and reports, from the stored runs
python scripts/run_exploratory_e1.py --parts tests && python scripts/report_exploratory_e1.py
python scripts/run_exploratory_e2.py --tests && python scripts/report_exploratory_e2.py
python scripts/run_intraday.py --horizon 1 --tests && python scripts/run_intraday.py --horizon 2 --tests
python scripts/report_exploratory_e3.py && python scripts/report_exploratory_summary.py
python scripts/run_exploratory_v3.py --parts tests && python scripts/report_exploratory_v3.py
```

Each stage refuses to run if an upstream stage was built under a different config. `docs/evaluation.md` describes the harness and tests. The exploratory model runs (intraday data, CPU models, and GPU jobs on the cluster with seeds merged by `scripts/merge_seeds.py`) are described in `docs/hpc.md`.

## Tests

```bash
PYTHONPATH=src pytest -q
```

Stage-contract tests are skipped when `data/` has not been built.
